# ADR-001: UI 完全自绘,Qt 只作为平台层

- 状态: 已采纳
- 日期: 2026-07-18

## 背景

编辑器对标 Houdini/Blender 级别的复杂度,需要节点图画布、3D 视口这类无法用
标准控件树承载的高性能自绘内容。最初方案是"QML 负责常规面板 + 自定义
QSGNode 负责节点图/视口"的混合架构(和 Houdini 实际的 Qt+自绘视口分工同构)。

## 决策

放弃 QML/场景图,整个 UI(包括常规面板、按钮、滑块、菜单)全部走自绘管线,
基于 `QWindow` + `QRhi`。Qt 只保留作为平台层:窗口生命周期、输入法(IME)、
剪贴板、原生文件对话框。不使用 QML 引擎和标准 Widget 控件树。

## 考虑过的替代方案

- 混合架构(QML 常规面板 + 自绘节点图/视口): 两套渲染世界拼接,状态同步
  和合成开销更高。否决。
- 完全绕开 Qt,自己接平台层(GLFW/SDL/原生 Win32/Xlib): 放弃 Qt 免费提供的
  IME、剪贴板、原生对话框支持,这些在中文输入场景下是真实的工程成本。否决。

## 后果

- 好处: 渲染管线彻底统一,不存在两套合成器拼接的问题;视口嵌入不再是
  "往布局树里挖洞塞原生 surface"这类脆弱集成。
- 代价: 需要自己实现文本整形/字体光栅化管线(FreeType + 未来可能的
  HarfBuzz)、立即模式部件库、命中测试与焦点管理、停靠布局系统 —— 这些
  在 QML 路线下是免费的。
- 中文 IME 支持的具体实现方式尚未落地,当前只保证架构上不排斥它
  (见 ADR-002 的文本管线设计)。
